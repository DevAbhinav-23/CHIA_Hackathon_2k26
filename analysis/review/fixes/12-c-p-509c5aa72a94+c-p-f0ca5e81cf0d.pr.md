# [CoreToFSM] Give the deasserted reset constant the reset's type

Fixes: <!-- fill in the issue number(s) -->

## Problem

`-convert-core-to-fsm` asserts in APInt during its internal canonicalization (`Bit widths must be the same` folding `comb.and`, c-p-509c5aa72a94; `Comparison requires equal bit widths` folding `comb.icmp`, c-p-f0ca5e81cf0d) when the state register is wider than one bit and its reset also feeds logic. Without an assertion build it emits ill-typed IR.

## Reproducer

`c-p-509c5aa72a94`:

```mlir
module {
  hw.module private @Foo(in %a : !seq.clock, in %b : i1, in %c : i1, out d : i1) {
    %c0_i2 = hw.constant 0 : i2
    %state = seq.compreg %state, %a reset %b, %c0_i2 : i2  
    %0 = comb.and %b, %c : i1
    hw.output %0 : i1
  }
}
```

```sh
circt-opt -convert-core-to-fsm repro.mlir
```

- Before (main @ 4738bd2685, assertions on, `--verify-each`): exit 134, `circt-opt: sdk/include/llvm/ADT/APInt.h:677: APInt &llvm::APInt::operator&=(const APInt &): Assertion `BitWidth == RHS.BitWidth && "Bit widths must be the same"' failed.`
- After: exit 0, valid IR, no diagnostic

`c-p-f0ca5e81cf0d`:

```mlir
module {
  hw.module private @Foo(in %a : !seq.clock, in %b : i1, out c : i1) {
    %c0_i2 = hw.constant 0 : i2
    %false = hw.constant false
    %state = seq.compreg %state, %a reset %b, %c0_i2 : i2  
    %0 = comb.icmp eq %b, %false : i1
    hw.output %0 : i1
  }
}
```

```sh
circt-opt -convert-core-to-fsm repro.mlir
```

- Before (main @ 4738bd2685, assertions on, `--verify-each`): exit 134, `circt-opt: sdk/include/llvm/ADT/APInt.h:1061: bool llvm::APInt::operator==(const APInt &) const: Assertion `BitWidth == RHS.BitWidth && "Comparison requires equal bit widths"' failed.`
- After: exit 0, valid IR, no diagnostic

## Root cause

In each state's output region and each transition's guard region the pass replaces the reset block argument by a constant 0 (the reset is modelled as deasserted), but creates that constant with `clonedRegValue.getType()`, the state register's type. An `i1` reset used by `comb.and`/`comb.icmp` then gets an `i2` operand. The active-low path already uses the argument's type.

## Fix

Create the constant with `blockArg.getType()` in both places.

## Commit message

```
CoreToFSM treats a register's reset as deasserted in the generated states
and replaces the reset block argument with a constant 0 in each state's
output region and each transition's guard region. That constant was
created with the type of the state register instead of the reset's own
type. When the state register is wider than one bit and the reset also
feeds other logic, its `i1` uses received an `iN` constant: the greedy
canonicalization then folded `comb.and`/`comb.icmp` on operands of
different widths and asserted in APInt (`Bit widths must be the same`,
`Comparison requires equal bit widths`), or the pass emitted ill-typed IR.

Create the constant with the block argument's type, as the active-low
reset path already does.
```
