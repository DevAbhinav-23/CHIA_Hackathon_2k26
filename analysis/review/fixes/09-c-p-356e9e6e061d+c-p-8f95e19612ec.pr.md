# [MooreToCore] Reject extract_ref types that have no LLHD projection

Fixes: <!-- fill in the issue number(s) -->

## Problem

Two crashes of the same patterns: `moore.extract_ref %arg0 from 0 : <i6> -> <struct<{a: i2, b: i2}>>` lowers to an `llhd.sig.extract` with a struct result, which fails verification (c-p-356e9e6e061d); `moore.dyn_extract_ref %arg0 from %arg1 : <open_uarray<i32>>, i32 -> <i32>` asserts in `cast<llhd::RefType>` because a reference to an open array converts to `!llvm.ptr` (c-p-8f95e19612ec). Integer references with a wider result and array references with a non-element, non-slice result produce invalid `llhd.sig.extract`/`llhd.sig.array_slice` the same way.

## Reproducer

`c-p-356e9e6e061d`:

```mlir

    %0 = moore.extract_ref %arg0 from 0 : <i6> -> <struct<{a: i2, b: i2}>>
    return %0 : !moore.ref<struct<{a: i2, b: i2}>>
  }
}
```

- After: exit 1, `repro.mlir:3:10: error: failed to legalize operation 'moore.dyn_extract_ref'`

## Root cause

Both patterns pick `llhd.sig.extract`, `llhd.sig.array_get` or `llhd.sig.array_slice` from the input type only. LLHD has no projection that reinterprets a reference as another type, so the remaining combinations cannot be lowered here, and open-array references are not LLHD references at all.

## Fix

A shared `isSupportedRefExtract` check runs first: input and result must be `llhd.ref`s, an integer input needs an integer result no wider than it, an array input needs its element type or a no-larger array of it. Otherwise the pattern fails and the conversion reports the op as not legalizable.

## Commit message

```
`ExtractRefOpConversion` and `DynExtractRefOpConversion` cast the converted
input to `llhd::RefType` and picked an LLHD projection from the input type
alone, without checking the result type:

- A reference to an open (dynamic) array converts to `!llvm.ptr`, so the
  `cast<llhd::RefType>` asserted, e.g. for
  `moore.dyn_extract_ref %a from %i : <open_uarray<i32>>, i32 -> <i32>`.
- An integer reference with a non-integer or wider result, e.g.
  `moore.extract_ref %x from 0 : <i6> -> <struct<{a: i2, b: i2}>>`,
  produced an `llhd.sig.extract` that fails verification. Likewise for an
  array reference whose result is neither its element type nor a narrower
  array of it, which produced an invalid `llhd.sig.array_slice`.

LLHD has no projection that reinterprets a reference as another type, so
these cannot be lowered. Check the converted types up front and fail the
pattern, which reports the op as not legalizable, instead of crashing or
emitting invalid IR.
```
