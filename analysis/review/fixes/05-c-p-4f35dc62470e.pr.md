# [DC] Reject !dc.value types that wrap a DC type

Fixes: <!-- fill in the issue number(s) -->

## Problem

`--lower-dc-to-hw` asserts in `Backedge::setValue` (`value.getType() == newValue.getType()`) on `dc.pack %a, %b : !dc.token`. A `!dc.value<!dc.token>` module port is also lowered to an ill-formed `!esi.channel<!dc.token>` without any diagnostic.

## Reproducer

```mlir
module {
  hw.module private @Foo(in %a : !dc.token, in %b : !dc.token, out c : !dc.value<!dc.token>) {
    %0 = dc.pack %a, %b : !dc.token
    hw.output %0 : !dc.value<!dc.token>
  }
}
```

```sh
circt-opt --lower-dc-to-hw repro.mlir
```

- Before (main @ 4738bd2685, assertions on, `--verify-each`): exit 134, `circt-opt: src/lib/Support/BackedgeBuilder.cpp:24: void circt::Backedge::setValue(mlir::Value): Assertion `value.getType() == newValue.getType()' failed.`
- After: exit 1, `repro.mlir:2:81: error: !dc.value cannot wrap DC type '!dc.token'`

## Root cause

`!dc.value` allowed any inner type, including `!dc.token` and `!dc.value`. Such a payload has no hardware meaning (a token carries no data and its own handshake would be dropped). DCToHW converts the result to `!esi.channel<!dc.token>` (the payload goes through `toHWType`, which leaves DC types alone) but the packed operand to `!esi.channel<i0>`, so connecting them asserts.

## Fix

Give `ValueType` a verifier that rejects DC inner types (and say so in its description). `dc.pack` and `dc.from_esi` infer their result type from an operand, so their `inferReturnTypes` now report such an operand instead of building the invalid type (which would assert in `ValueType::get`).
