# [CoreToFSM] Deassert removed reset arguments in transition actions

Fixes: <!-- fill in the issue number(s) -->

## Problem

`-convert-core-to-fsm` produces IR that crashes the verifier after the pass (segfault in `OperationVerifier::verifyOpAndDominance`, no CIRCT frame) when a register's reset also feeds a variable register's next value.

## Reproducer

```mlir
module {
  hw.module private @Foo(in %a : !seq.clock, in %b : i1, in %c : i4) {
    %c0_i2 = hw.constant 0 : i2
    %c0_i4 = hw.constant 0 : i4
    %state = seq.compreg %state, %a reset %b, %c0_i2 : i2  
    %0 = comb.mux %b, %c, %c0_i4 : i4
    %var = seq.compreg %0, %a reset %b, %c0_i4 : i4  
    hw.output
  }
}
```

```sh
circt-opt -convert-core-to-fsm repro.mlir
```

- Before (main @ 4738bd2685, assertions on, `--verify-each`): exit 139, `Stack dump:`
- After: exit 0, valid IR, no diagnostic

## Root cause

The pass removes the reset arguments of the state registers from the generated `fsm.machine` and replaces their uses by the deasserted value in output and guard regions. Action regions, which compute the next values of variable registers, mapped every block argument to the machine's argument instead, so the reset kept a use there; erasing the argument left a dangling operand.

## Fix

Record the deasserted value of each removed reset argument (0 for an active-high reset, 1 for the operand of an active-low one; the set becomes a map) and substitute it in action regions too, before they are canonicalized.
