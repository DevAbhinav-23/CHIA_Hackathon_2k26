# [Moore] Verify class declaration base classes

Fixes: <!-- fill in the issue number(s) -->

## Problem

`--convert-moore-to-core` segfaults on a class that extends an undefined symbol (null `Operation*` cast in `resolveClassStructBody`). It asserts if the symbol names another op, and a cycle of `extends` clauses recurses until the stack overflows.

## Reproducer

```mlir
module {
  moore.class.classdecl @Derived extends @MissingBase attributes {sym_visibility = "private"} {
  }
}
```

```sh
circt-opt repro.mlir --convert-moore-to-core
```

- Before (main @ 4738bd2685, assertions on, `--verify-each`): exit 139, `Stack dump:`
- After: exit 1, `repro.mlir:2:3: error: 'moore.class.classdecl' op base class @MissingBase does not name a 'moore.class.classdecl'`

## Root cause

`ClassDeclOp` was not a symbol user, so nothing checked its `base` reference. MooreToCore's `resolveClassStructBody` assumes the base names a class declaration and that the inheritance chain is acyclic.

## Fix

Make `ClassDeclOp` implement `SymbolUserOpInterface`; `verifySymbolUses` checks that the base class resolves to a `moore.class.classdecl` and walks the base chain (with a visited set) to reject a class that inherits from itself.
