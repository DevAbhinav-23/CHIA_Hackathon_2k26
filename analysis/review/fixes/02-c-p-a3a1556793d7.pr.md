# [OM] Verify that every class field name has a type

Fixes: <!-- fill in the issue number(s) -->

## Problem

An `om.class.extern` written in generic form with a field name but no field type crashes the verifier of an `om.elaborated_object` that refers to it (null `std::optional` dereference in `ElaboratedObjectOp::verifySymbolUses`). Printing such a class in custom form crashes too (`printClassLike`).

## Reproducer

```mlir
"om.class.extern"() ({
^bb0:
}) {sym_name = "Extern", formalParamNames = [], fieldNames = ["x"], fieldTypes = {}} : () -> ()
om.class @Test() {
  %0 = om.constant 0 : i32
  %1 = "om.elaborated_object"(%0) <{className = @Extern}> : (i32) -> !om.class.type<@Extern>
  om.class.fields
}
```

```sh
circt-opt repro.mlir --mlir-print-local-scope --mlir-print-debuginfo
```

- Before (main @ 4738bd2685, assertions on, `--verify-each`): exit 134, `Stack dump:`
- After: exit 1, `repro.mlir:1:1: error: 'om.class.extern' op field "x" has no type`

## Root cause

The custom parser of `om.class`/`om.class.extern` always builds matching `fieldNames`/`fieldTypes`, but the verifier did not require it, so generic-form IR can break the invariant. `om.class` happens to be caught later by `verifyRegions` (with a misleading message); `om.class.extern` is not checked at all.

## Fix

`verifyClassLike`, shared by both ops, now checks that each field name is a string with a type in `fieldTypes`.

without an entry in `fieldTypes`; the custom parser never produces this,

`getFieldType(name).value()` on the missing entry: verifying an

Check in `verifyClassLike`, shared by `om.class` and `om.class.extern`,
