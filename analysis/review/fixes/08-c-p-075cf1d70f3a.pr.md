# [MooreToCore] Lower moore.dyn_extract of integers to any bitcastable type

Fixes: <!-- fill in the issue number(s) -->

## Problem

`--convert-moore-to-core` emits invalid IR for `moore.dyn_extract %arg0 from %arg1 : i4, i32 -> array<2 x i2>`: `'comb.extract' op result #0 must be a signless integer bitvector, but got '!hw.array<2xi2>'`. A result wider than the input (`i8 -> i32`) gives `'comb.extract' op from bit too large for input`, and an array input with an integer result an `hw.array_slice` with an integer result.

## Reproducer

```mlir
module {
  func.func private @dyn_extract_array(%arg0: !moore.i4, %arg1: !moore.i32) -> !moore.array<2 x i2> {
    %0 = moore.dyn_extract %arg0 from %arg1 : i4, i32 -> array<2 x i2>
    return %0 : !moore.array<2 x i2>
  }
}
```

```sh
circt-opt repro.mlir --convert-moore-to-core
```

- Before (main @ 4738bd2685, assertions on, `--verify-each`): exit 1, `repro.mlir:3:10: error: 'comb.extract' op result #0 must be a signless integer bitvector, but got '!hw.array<2xi2>'`
- After: exit 0, valid IR, no diagnostic

## Root cause

The integer path built `comb.extract` directly with the converted result type; the array path built `hw.array_slice` for anything that is not the element type. The constant-offset `ExtractOpConversion` already handles packed aggregate results by extracting bits and bitcasting.

## Fix

Integer input: zero-extend the input if the result is wider (bits above the input read as zero, as for constant offsets), shift, extract the result's bit width and `hw.bitcast` to the result type when it is not an integer. Array input: fail the pattern unless the result is the element type or an array of it, as `ExtractOpConversion` does.

## Commit message

```
`DynExtractOpConversion` assumed that a dynamic extract out of an integer
yields an integer no wider than the input, and that one out of an array
yields an element or a slice. Other result types, which
`ExtractOpConversion` already handles for constant offsets, produced
invalid IR: `moore.dyn_extract %x from %i : i4, i32 -> array<2 x i2>`
became a `comb.extract` with an `!hw.array` result, a result wider than
the input a `comb.extract` past the input's width, and an array input with
an integer result an `hw.array_slice` with an integer result.

For integer inputs, extract the result's bit width and bitcast it to the
result type, zero-extending the input first when the result is wider (the
bits above the input read as zero, as for the constant-offset case). For
array inputs, reject results that are neither the element type nor an
array of it, as `ExtractOpConversion` does.
```
