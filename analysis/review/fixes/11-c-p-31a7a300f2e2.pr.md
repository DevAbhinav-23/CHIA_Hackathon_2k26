# [CombToSynth] Lower comb.icmp with zero-width operands

Fixes: <!-- fill in the issue number(s) -->

## Problem

`convert-comb-to-synth` asserts on `comb.icmp ult %a, %b {synth.test.arch = "KOGGE-STONE"} : i0` (`width must be positive` in `LazyKoggeStonePrefixTree`). Sklansky and Brent-Kung index an empty vector instead; signed `i1` comparisons with any prefix architecture hit the same code (their magnitude is zero-width); `eq`/`ne` on `i0` build an empty `and_inv`/`or` and assert; signed `i0` comparisons are rejected as unsupported.

## Reproducer

```mlir
module {
  hw.module private @Foo(in %a : i0, in %b : i0) {
    %0 = comb.icmp ult %a, %b {synth.test.arch = "KOGGE-STONE"} : i0
    hw.output
  }
}
```

```sh
circt-opt repro.mlir '--pass-pipeline=builtin.module(hw.module(convert-comb-to-synth{additional-legal-ops=comb.xor,comb.or,comb.and,comb.mux},cse))'
```

- Before (main @ 4738bd2685, assertions on, `--verify-each`): exit 134, `circt-opt: src/lib/Conversion/CombToSynth/CombToSynth.cpp:836: (anonymous namespace)::LazyKoggeStonePrefixTree::LazyKoggeStonePrefixTree(OpBuilder &, Location, int64_t, ArrayRef<Value>, ArrayRef<Value>): Assertion `width`
- After: exit 0, valid IR, no diagnostic

## Root cause

`constructUnsignedCompare` only falls back to ripple carry (which handles zero bits) when that architecture is selected; the prefix-tree paths need at least one bit. The `eq`/`ne` paths reduce over the bits of `lhs ^ rhs`, which are empty for `i0`.

## Fix

All zero-width values are equal, so an `i0` comparison becomes the constant result for equal operands, via the Comb folder's `applyCmpPredicateToEqualOperands` (exported from `CombOps.h` instead of adding a third copy). Zero-width magnitudes inside signed comparisons use the ripple-carry comparator. The now-dead "i0 signed comparison is unsupported" bail-out is removed.

## Commit message

```
The `comb.icmp` lowering assumed its operands have at least one bit:

- unsigned comparisons built a parallel-prefix tree over zero bits when an
  architecture other than ripple carry was selected, so Kogge-Stone
  asserted (`width must be positive`) and Sklansky/Brent-Kung indexed an
  empty vector;
- signed `i1` comparisons hit the same path, because their magnitude
  (all bits but the sign) is zero-width;
- `eq`/`ne` built an `and_inv`/`or` over an empty bit list and asserted;
- signed `i0` comparisons were rejected as unsupported.

All zero-width values are equal, so fold an `i0` comparison to the result
for equal operands (reusing the Comb folder's
`applyCmpPredicateToEqualOperands`, now exported from CombOps.h), and use
the ripple-carry comparator, which handles zero bits, for zero-width
magnitudes.
```
