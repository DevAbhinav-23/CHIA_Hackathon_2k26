# [CombToSynth] Fix shift lowering when no shift amount is in bounds

## Problem

## Root cause

`createShiftLogic` builds a mux tree over the results for the in-bounds amounts `[0, maxShiftAmount)` and falls back to the padding for `maxShiftAmount`. Shifts of `i0` and arithmetic right shifts of `i1` have `maxShiftAmount == 0`, so the tree has no leaves; for `i0` the padding is also the null "i0 value" that the helper documents.

## Fix

Materialize a null padding as `hw.constant 0 : i0`, and return the out-of-bounds value directly when no shift amount is in bounds. That is the exact result: an `i0` shift yields the only `i0` value, and an `i1` arithmetic right shift always yields the sign bit, i.e. the operand.
