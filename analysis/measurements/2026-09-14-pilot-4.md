## 5. Defects found

**D-1 (new). A stage-2 turn that raises leaves no record of what raised.**
`generate_seeded` catches every exception into a `failure` string
(`turn_failed:<type>`) and returns it; `_drive_seed` reads that string only to
test it for `SpendCapRefused` and then drops it. Nothing writes it to the
ledger, the counters or the artefact tree. What is recoverable after the fact
is: the node was charged 12.4 s after stage 1's 71.5 s; `llm_probe_write.prompt.md`
was written, so the prompt rendered and `corpus.resolve_sites` succeeded;
`llm_probe_write.{md,jsonl,stderr}` are empty and its `usage.json` is `{}`, so
`dispatch_turn` raised rather than returning a failed `QueryResult`; the LLM
worker's log shows the backend was constructed for a SECOND turn, so the
refusal was not `SpendCapRefused` at `authorise`, which happens before
dispatch. The type itself is not recoverable from any artefact and NO LIVE
RETRY WAS MADE. The fix is to persist the `failure` string, not to guess it.

**D-2 (new). The mutation arm's three probes were all rejected by the tool.**
`any.argv.flag_delete`, `mlir.op.line_swap` and `mlir.type.i0_zero` each
produced `parse_error:tool_rejected_input` on the Moore seed, so the arm ran
its whole window in 1.5 s and observed nothing. Measured, not diagnosed.
