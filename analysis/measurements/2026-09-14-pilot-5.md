## 4. The three fixes, measured

**Fix 1, a turn that raises leaves a record.** `turn_failed.txt` is in the
iteration directory, naming `PromptContractError`, its message `no_block` and
the traceback down to `parse_json_footer`. Pilot 4's D-1 cannot recur.

**Fix 2, the mutation arm runs the seed's own test first.** `seed_input.mlir`
and `seed_build.stderr` are in the iteration directory, the stderr opening
`error: custom op 'moore.conversion' is unknown`: `circt-opt` rejects the seed's
own unmutated `test/Conversion/MooreToCore/errors.mlir` at the build commit, so
the arm returned `stale_at_build` with no specs in 0.1 s. Pilot 4 spent its
whole mutation window on three mutants of that text, all rejected for this.

**Fix 3, the argv carries neither lit option.** Nothing changed here, and the
measurement says why: `corpus.strip_probe_only_options` already removed both
spellings of `-verify-diagnostics` and `-split-input-file`, and pilot 4's
`argv.json` records argv without them. On the run's own image `circt-opt`
prints the diagnostic verifier's `expected error ... was not produced` lines
whether or not the option is given and only the option turns them into exit 1,
so what pilot 4's stderr carried was noise over a real parse error underneath.

## 5. Defects found

**D-3 (new). The forced final answer answered with a function call.** Stage 2
spent all 12 tool iterations on `read_file`, `grep` and `list_dir`, never
called `write_probe`, and the thirteenth call - the one made with the tool
declarations kept and `tool_config` mode NONE, which is W-18e's own fix - came
back `finish=STOP, parts=['function_call']`. The backend logged `the final
answer was empty`, returned `result=""`, and `parse_json_footer` refused it.
Mode NONE held for stage 1 in the same run and in pilot 4; it did not hold
here. Two things are wrong and only the second is the backend's: the prompt
told the model to write the files FIRST and it read source for twelve calls
instead, so even a well-formed footer would have named files that do not
exist; and a final answer that is still allowed to emit a `function_call` part
buys the turn nothing.

**D-4 (new, transient). A rate-limited turn is discarded whole.** Step 3's live
replay met HTTP 429 on its first `generateContent`; CHIA's `prompt()` never
retries a `RateLimitError`, so it propagated and the stream and the usage went
with it, leaving exactly pilot 4's fingerprint - a written prompt, three empty
files, a 3-byte `usage.json`. Pilot 4's own exception type stays unrecoverable
and IS NOT CLAIMED to have been this one: its occupancy was 12.4 s and the
replay's 274 s.
