| `vertex-usage.patch` (`chia/models/vertex.py`) | Token accounting **and a per-turn money ceiling** in `VertexGeminiLLM`, additive. (1) Sums `thoughts_token_count` and `tool_use_prompt_token_count` into `_last_metadata` as `thinking_tokens` and `tool_use_prompt_tokens`: both are billed and both are separate fields from `candidates_token_count` / `prompt_token_count` in `google-genai`, so every priced turn was understated and the USD cap bound late by an unknown factor (K11). (2) Finalises `_last_metadata` in a `finally`, so a turn that raises after N `generate_content` calls reports the tokens it consumed instead of an empty dict a caller then prices at zero (K10). (3) Adds a constructor option `turn_budget_usd`: before each `generate_content` call the tool loop prices what it has spent so far and estimates the next call from the CONVERSATION's current size (characters / 2.0 at the input rate, plus `max_tokens` at the output rate), and raises the new `TurnBudgetExceeded` - a `VertexError`, in `prompt()`'s never-retry list - before sending when the two would pass the ceiling. Without it one turn's input tokens grow quadratically in the tool-call count and a caller's pre-authorisation bounds one call out of up to `max_tool_iterations`: MEASURED, W-18, three turns made 14, 21 and 37 calls and cost 19.7x, 32.3x and 64.1x what was authorised (errata row 38). `turn_budget_usd` defaults to None, which is CHIA's behaviour unchanged. (4) Bounds `_get_node_id`, which all four error paths call: it asks Ray nothing when `ray.is_initialized()` is false, and gives up on the answer after `NODE_ID_TIMEOUT_SECONDS` when it is true. With a stale `/tmp/ray/ray_current_cluster`, `ray.get_runtime_context()` retries the GCS for ever and Ray's own client terminates the process after sixty seconds, so a 429 on such a machine hung a whole campaign (errata row 37). Neither existing sum is touched and the exception behaviour of every pre-existing path is unchanged; CHIA's own `chia/models/tests/test_vertex.py` passes unaltered on the patched file (**37 passed, 11 skipped, re-verified 2026-09-16 with the W-18b additions**, same as unpatched). |

The fix round wires that staging; until it lands, only `sync-to-chia.sh` applies them, and it applies `issue_task-vertex-branch.patch` alone. `circt_bug_loop/tests/test_upstream_patches.py` holds both patches applying at commit 16c35e92 and the two behaviours the vertex patch exists for.
