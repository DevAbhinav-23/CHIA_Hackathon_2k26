\begin{abstract}
CIRCT is an open-source compiler that turns hardware descriptions into Verilog,
so a defect in it can corrupt a chip unnoticed. Agents that repair CIRCT feed on
its issue tracker, which only scarce maintainer attention drains. We built a
loop that makes its own supply: an agent reads one of 187 CIRCT fix commits
mined from 24 months, % 187 fix-shaped commits over 24 months: analysis/pin-window-analysis.md, headline table and lines 112-113
171 rebuildable from a prebuilt SDK, % 171 of 187 have an exactly matching prebuilt-LLVM SDK: analysis/pin-window-analysis.md line 14
names the class of mistake it corrected, and writes inputs probing for it
elsewhere. Fixed tools, not the model, build, judge, minimise, deduplicate and
repair; a named person approves every filing. CHIA's CIRCT image compiles
out the compiler's own consistency checks, so nothing can fire; % CHIA's published chia-circt image: 606 of 606 compile commands carry -DNDEBUG, circt-opt has 0 undefined __assert_fail: analysis/measurements/2026-09-13-frd-followups.md lines 469-470, A-10
restored, they reach 536 of 555 compiler objects % 536 of 555 obj.CIRCT objects reference the assertion handler: analysis/measurements/2026-09-14-image-build.md 4, FR-03.5
and leave CHIA's test gate at 1,119 passes and 0 failures, identical with them
off. % 1,119 passed / 0 failed of 1,127 considered, identical in both images: analysis/measurements/2026-09-14-image-build.md 5 run 2 and W-04b 3
Replaying six real CIRCT failures exposed two defects that would have misrouted
three of four bugs. % 6 confirmed fixtures of 7 attempts: analysis/measurements/2026-09-14-crash-fixtures.md 1; the two frame defects and "three of the four real bugs are out of scope": same file 3.2 and 3.4
We release the loop as CHIA nodes and tools; the pre-registered campaign against a
mutation fuzzer is running, and will report its maintainer-confirmed bug count.
\end{abstract}

\section{Introduction}
CIRCT is an open-source compiler for hardware. A designer writes how a circuit
should behave, in FIRRTL (the form the Chisel hardware language produces) or in
SystemVerilog, and CIRCT lowers it to Verilog, which synthesis and layout tools
turn into a chip. It is built on MLIR, the LLVM project's compiler
framework, and inherits LLVM's way of testing: a regression test carries the
command to run and the output to expect, run by a tool called \texttt{lit}. A CIRCT bug that
crashes the compiler is an inconvenience, seen and worked around; a bug that
makes it emit wrong Verilog is not: the output is well formed, passes the tools
below it, and can reach fabrication unnoticed.

CHIA \cite{chia} is the agent framework this hackathon is built on. Its issue
solver for CIRCT chains six phases, from assessing an issue to reproducing,
fixing, verifying against the whole test suite, repairing regressions and
writing the pull request; on 16 CIRCT issues it fixed five, three of them
merged.

Its supply is the constraint. Over the past year CIRCT received 82 bug-labelled
issues and closed 65, so the project is neither short of reports nor ignoring
them; what does not drain is the backlog of 101 open ones, at a median age of
911 days. The scarce resource is maintainer attention, and an
agent that empties the queue faster creates none. What would help is a bug that
arrives already minimised, already checked against what is known, already
carrying a candidate fix, from a source that files nothing else. Past fixes are the unspent information: a commit that
corrects one wrong assumption inside a pass usually leaves the same assumption
at other sites, and CIRCT ships no fuzzing infrastructure to find them.

This paper describes a loop that manufactures its own supply and then withholds
most of it: the loop as built (Section~\ref{sec:loop}), the preconditions we
measured and repaired first (Section~\ref{sec:pre}), a pre-registered
head-to-head against a mutation fuzzer (Section~\ref{sec:eval}), and its result
(Section~\ref{sec:res}).

\section{The Loop}\label{sec:loop}
Fig.~\ref{fig:loop} names the stages and marks the ones the agent runs; tools
decide everything else, so no number in the result comes from inside the model.
One model serves every agent stage, Gemini 3.8 Flash through CHIA's Vertex
backend, % model and backend, express mode: design/ADR/ADR-D-03-model-backend.md, superseding decision 2026-09-14
and no stage can build a client for it unless one environment variable
is set for that run, so a test or a dry run cannot reach the model. % live-call interlock BUGLOOP_ALLOW_LIVE_MODEL: ADR-D-03 rule (1); design/03-LLD.md 3.5.1

\textbf{Read the seed (1).} A seed is one of 187 CIRCT commits from the last two
years that look like bug fixes, with its diff and the test its author added or
changed. The agent reads both, states in one sentence the root-cause class
the fix corrected, and names other sites where the same assumption still stands.
The record carries that diff and those tests, so the worker needs no clone of
CIRCT's history. % SeedRecord carries diff and test_files, contract 2.0: design/00-README.md, seam rule

\textbf{Write probing inputs (2).} The seed's own test decides the language,
because its command line names the tool through which the bug was reachable:
\texttt{circt-opt}, which runs a named sequence of passes over an intermediate
file; \texttt{firtool}, the driver from FIRRTL to Verilog; or the SystemVerilog
front end. About 127 of the 187 seeds sit in code no FIRRTL input can reach, so
a FIRRTL-only generator would miss most of the corpus. The agent reads the
compiler's source and writes each candidate through tools of its own, and runs
no command.

\textbf{Build (3).} CIRCT compiles against one pinned commit of LLVM and MLIR,
and Section~\ref{sec:pre} explains how the loop avoids building those from
source. The build compiles in CIRCT's assertions, the internal checks its own
authors wrote, which stop the compiler the moment an assumption breaks.

\textbf{Judge (4).} An oracle is the rule that decides whether an input found a
bug. The primary one admits no argument: the compiler crashed, or an assertion
fired. A second runs the same design through CIRCT's simulator and
through Verilator, and treats disagreement as suspicious; it reports
only, because the two disagree routinely over uninitialised and reset signals.

\textbf{Reduce (5).} A crashing input is usually large and mostly irrelevant to
the crash. \texttt{circt-reduce}, which CIRCT ships, deletes parts of it and
keeps each deletion while the failure survives; a textual reducer takes over
where that tool dies on the input itself.

\textbf{Triage and report (6).} Many failures are one failure, and deciding
which are the same is mechanical: a fingerprint is the assertion text with its
source location, or, for a crash, the symbolised frames left once the crash
handler's prologue is stripped. Survivors are matched against a local mirror
of CIRCT's open and closed issues and against commits made since the build
point. The agent's share is the last part, writing the report, and no gate reads
what it concluded. % gate reads no triage classification: design/03-LLD.md 3.9 (FR-13.4)

\textbf{Repair (7).} CHIA's phase chain runs unaltered but for one added branch
selecting the backend the rest of the loop uses, and an entry point taking a
local report in place of a GitHub issue. Repair is restricted to crashes and
assertion failures, where nobody has to argue about what the right answer was.

\textbf{The gates.} Between stages sit questions with two answers, the bars that
pinch the ribbon in Fig.~\ref{fig:loop}. A no ends the iteration and returns its
reason to the agent with the verdicts and reduced cases. The last is a gate of four questions, each
answered by a tool: does the failure reproduce in a fresh process on another
worker, is the case minimal, is the input valid, and is it new. % four mechanical gate questions: design/03-LLD.md 3.9 (FR-13.1)
The third is
three parse-and-verify commands, one per input language, and a clean rejection
makes the input the loop's own fault rather than the compiler's. % gate question 3, the three commands: design/03-LLD.md 4.8 (FR-13.15)
Then the gate
is a person: a named author approves every filing at a command line, under a cap
on filings per day, and nothing is filed by default. % approval CLI, python -m circt_bug_loop.approve: design/03-LLD.md 16.2, 13.2 errata

\section{Measured Preconditions}\label{sec:pre}
The loop has to build CIRCT at arbitrary points of its history, and the compiler
has to be able to complain. Neither held when we started. Table~\ref{tab:meas}
is what we measured on the image the loop now runs; this section gives the
conclusions.

\textbf{Building the past cheaply.} CIRCT records the exact LLVM commit it expects, the pin; a build against any other fails outright rather than degrading, and compiling that LLVM from source costs hours per seed. It also publishes an SDK, a tarball of prebuilt LLVM and MLIR libraries recording its own pin, and where an SDK shares a seed's pin CIRCT rebuilds in minutes: of 187 fix-shaped commits mined from 24 months, 171 match exactly.



The same mechanism fixes where the loop runs: not the newest commit of CIRCT's
main branch, whose pin has no published release today, but release-pinned main,
the newest commit whose pin has one, which for this image is 8 commits and 4.8
days behind the head. % lag measured at eade0de6 with SDK firtool-1.159.0: analysis/measurements/2026-09-14-image-build.md 1; ADR-D-10 first application
A long lag mechanically lowers the filing rate, because
more candidates come back already fixed.

\textbf{Letting the compiler complain.} Optimised builds delete assertions by defining the macro \texttt{NDEBUG}, and
CHIA's published CIRCT image is such a build: its binaries hold no reference to
the assertion handler, so a loop whose oracle is a failed assertion would find
nothing under it, whatever the agent wrote. One compiler
flag, \texttt{-UNDEBUG}, puts them back, and the image the loop runs is that
build at release-pinned main, with the flag in every compile command and the
handler back in all but 19 of its 555 compiler objects, which assert nothing. % 536 of 555 objects reference the handler: analysis/measurements/2026-09-14-image-build.md 4, FR-03.5

Whether the restored checks fire on CIRCT's own tests is what the oracle rests
on, so we built the image twice, differing in that flag alone, and ran CHIA's
whole test gate in both: the two runs pass the same 1,119 tests and fail none. % 1,119 of 1,127 considered, 0 failed, identical in both images: image-build.md 5 run 2 and W-04b 3
The set of tests that pass with assertions compiled out and fail with them
compiled in is therefore empty, so a probe that trips an assertion trips it
because of what the probe does, and Table~\ref{tab:meas} prices the flag.

One defect had to be repaired first: at CIRCT commits after mid-2026 a test
directory's configuration file raises while \texttt{lit} is discovering tests,
and CHIA's exclusion of that directory is applied after discovery, so the gate
discovered nothing. Pointing the build at the SDK as its MLIR source root, one
flag, restores discovery. % lit then discovers 1,390 tests with 0 parse errors: 2026-09-14-image-build.md 4 (FR-03.17) and 5
The binary still calls itself an optimised build,
so every report names the flag.

\textbf{Tested on real failures.} The oracle and its fingerprints were calibrated on real output: six past CIRCT
bugs, rebuilt at the commit before their fix and recorded with input, argument
vector and error output, in three classes across two SDK releases at 14\,s to
601\,s of build each. % six fixtures, three classes, two SDK tags, build costs: analysis/measurements/2026-09-14-crash-fixtures.md 1 and 2
Two defects in the fingerprinting rules appeared only
there: the name normaliser erased every frame in an anonymous namespace, which
is where CIRCT's passes live, and the scope test read an inlined frame instead
of the physical one, putting three of the four real bugs outside the repair
stage's reach. % the two frame defects: 2026-09-14-crash-fixtures.md 3.2 and 3.4; design/reviews/implementation-errata-log.md W-08 rows 1 and 2
Both are fixed, and each fixture now pins the corrected
answer.

\section{Evaluation Design}\label{sec:eval}
The experiment asks whether reading a past fix makes an agent better at finding
new bugs than mutating the same tests at random. Two arms run the same harness,
oracles, reducer and gate, and only the generator differs: the seeded arm is
stages 1 and 2 above, and the mutation arm mutates the same seed tests
syntactically without ever seeing the diff or the root-cause class, following
Mut4All's design for mutators synthesised by a language model \cite{mut4all}.

Both arms spend the same pre-registered budget, whose unit is one elapsed
wall-clock second of an arm's fixed window: they run one after the other, each
for four hours, on the same cluster at the same concurrency.
Safety caps bound damage rather than effort, at 2,000 generated inputs per arm
per day, 3 filings per day and 10 in the campaign, every probe held to 60
seconds and 4\,GiB, and a hard cap of 200 US dollars on model spending stops
both arms. % window 14,400 s per arm, the three caps and campaign_spend_cap_usd: circt_bug_loop/budget.yaml
All of it is committed before the campaign starts, so no threshold
can be chosen afterwards.

The headline is the number of distinct bugs a CIRCT maintainer confirmed, by
labelling, commenting on or fixing them, within that budget; our own oracle
agreeing with itself produces a candidate, not a bug. Table~\ref{tab:res} names
the five secondary counts.

\textbf{Deduplication.} Two candidates are one bug when a single primary
fingerprint is equal, computed after the crash handler's own prologue is
stripped from the trace. On a hand-labelled set of 22 candidate pairs the rule
collides on 1 of the 11 distinct pairs and falsely merges 1 of the 11 duplicate
pairs; % 22 labelled pairs, collision 1/11, false merge 1/11: design/reviews/implementation-errata-log.md W-10 row 20
both rates are printed beside the headline, since a collision inflates
that count and a false merge deflates it.

\textbf{Known issues.} A mirror of the tracker, refreshed once per run, answers
whether a candidate is already reported. GitHub stops paginating an
issue listing at its hundredth page, which the loop met as an error and not as
truncation, so the mirror walks newest first, then oldest first, and unions
the two: 600 issues cost 35 requests and half a minute. % 422 at page 100; 600 issues in 35 requests, 33.9 s: implementation-errata-log.md W-14 row 21

\textbf{Contamination.} CIRCT's history sits in the training data of any model
we can use, so the agent may reproduce a fix it memorised. Every candidate is
screened against fixes made after its seed, at the level of the symbols the
seed's fix touched: that screen flags 77\% of the corpus where the same screen
at file level flags 96\%. % symbol level 77.0%, file level 96.3%: analysis/measurements/2026-09-13-frd-followups.md M4
A real crash is a real crash, so the flag qualifies a
candidate and reports it apart rather than excluding it. The repair stage runs CHIA's executor unchanged and is
not screened. We post the method to the project's forum before the campaign
starts, and leave issues marked as good first issues to human newcomers.

\textbf{Failure taxonomy.} Every candidate reaching the gate is recorded with
its verdict, one of unreproducible, not minimal, invalid input, duplicate,
undecided or new bug, and every repair attempt with the phase that failed, so the record shows
where budget went without return.

\section{Related Work}
\textbf{Agentic repair.} SWE-bench \cite{swebench} scores agents on real GitHub
issues and set the pattern this work inherits; CHIA's issue solver \cite{chia}
applies it to a hardware compiler. Both draw from a queue; we add the stage that
fills one.

\textbf{Compiler fuzzing.} CSmith \cite{csmith} generates random C programs and
found bugs throughout production C compilers. For MLIR, MLIRod mutates along
operation dependencies \cite{mlirod}, N\"uwa adds generation driven by a
language model \cite{nuwa}, DESIL targets silent wrong-output bugs
\cite{desil}, and FLEX interleaves learning with exploration,
finding 80 previously unknown bugs in a 30-day campaign \cite{flex}. None of them repairs
or withholds. Mut4All synthesises mutators from past bug reports \cite{mut4all},
and our mutation arm follows its design.

\textbf{Seed-guided generation, reduction, gating.} AFuzz \cite{afuzz} is the
origin of our method: given a reference bug, an agent analyses the root cause,
hypothesises where else that cause could live, and tests each hypothesis with
generated code, finding 40 bugs in V8 in a month. We apply it to a hardware
compiler, behind a repair chain and a gate. Delta debugging
\cite{deltadebug} is the algorithm stage 5's reducer implements, and we
contribute only its placement. Abstain-and-Validate raises repair success by
letting a second model decline a bug and reject a patch \cite{abstain},
llvm-harness packages LLVM's middle end for agents \cite{llvmharness}, and
CodeRover-S repairs security bugs found by OSS-Fuzz \cite{coderovers}; each
makes an existing repair agent more selective, while our gate sits downstream,
decides what reaches a human at all, and discards by default.

\section{Artefact and Limitations}
We release the loop as CHIA nodes and tools, the framework's own units of
composition, so swapping the generator for the mutation arm is one node
substituted. Its two halves, the one that proposes work and the one that
measures it, meet at a single frozen contract of seven record types and one
function call, version 2.1, and are tested separately against recorded examples
of it; % contract 2.1, seven schemas plus one interface, tag contract-2.1: design/00-README.md, seam rule; circt_bug_loop/contract/FROZEN.md "Contract 2.1" (adds BuildStatus tool_unavailable, MINOR)
the suite is 644 tests, of which 594 need no cluster, no
network and no model. % 2026-09-14, at HEAD: pytest circt_bug_loop/tests -q --co = 644 collected; -m t0 = 594, -m "t0 or t1" = 627, -m t2 = 9, -m t3 = 7
Four
things go upstream to CHIA: the Dockerfile for the assertions-on image, its
build workflow, three helpers for CHIA's own CIRCT module, and the nineteen-line
branch that lets its repair chain select the backend this loop runs on. % upstream/: dockerfiles/ChiaCirctAssertDockerfile, .github/workflows/chia-circt-assert.yml, chia-chipyard-circt-additions.py, issue_task-vertex-branch.patch (19 insertions; ADR-D-03 addendum)
All of it, with the seed corpus and every input, verdict, reduced
case, transcript and gate decision, is at
\url{https://github.com/DevAbhinav-23/CHIA_Hackathon_2k26}.

The apparatus is verified a stage at a time, and the strongest piece of that
evidence is the second oracle's harness generators: from one generated design
they emit a CIRCT simulation harness and a Verilator testbench printing
identical 112-line sequences, and one changed constant makes them disagree at a
named cycle and signal. % identical 112-line sequences, A-08 closed: docs/HANDOFF.md W-08 done; implementation-errata-log.md W-08 row 14

\textbf{What is not built.} The pre-registered campaign has not run; the live
model calls so far are the mutator synthesis and a pilot. % the interlock is now opened deliberately per run: ADR-D-03 rule (1); docs/HANDOFF.md W-12b and W-18
The first live model turn, the one that synthesised the mutator set, billed
625{,}478 tokens, 2{,}975 of them thinking, for USD 0.49. % analysis/measurements/2026-09-16-mutator-synthesis.md 9.3: 619,603 in + 2,900 out + 2,975 thinking = 625,478; cost_usd 0.486733
The 187 seeds rest on a
subject-keyword filter, no diffs read to confirm each is a bug fix; of seven
mining attempts, one seed did not fail at its parent. % 6 confirmed of 7 attempted, the discard recorded: analysis/measurements/2026-09-14-crash-fixtures.md 1
How many seeds the second oracle applies to has not been counted, % A-19 still open: implementation-errata-log.md W-08 row 14
the contamination screen misses a sibling fixed in a commit whose
subject does not name it, and CHIA's repair chain returns no token counts for
its own turns, so the reported spend excludes that stage. % stage 7 token capture unavailable, spend a lower bound: design/ADR/ADR-D-03-model-backend.md addendum
The image is built but not published, so a report names its content hash rather
than a registry digest.

\textbf{Scope.} The loop does not repair wrong-output bugs, because the oracle
that would find them is report-only, and it does not replace maintainers: it
converts the human event from writing a bug report into reading one.
