\begin{abstract}
Software bugs in hardware compilers like CIRCT risk injecting silent defects
into physical chips. AI repair agents can fix known issues, but they are
constrained by the slow trickle of human-reported bugs. We present a closed
loop, built on the CHIA agent framework, that mines historical CIRCT commits to
generate its own defect supply: a model learns the mistake pattern behind each
of 187 past fixes % 187 fix-shaped commits over 24 months: analysis/pin-window-analysis.md
and synthesises novel, bug-exposing inputs. The loop offloads building, judging,
test reduction and deduplication entirely to deterministic tools, hands patch
generation to CHIA's existing repair chain, and reserves human effort
exclusively for final filing approval. It restores the compiler's internal
assertions, compiled out of CHIA's published image, in 536 of 555 objects, % 606/606 compile commands -DNDEBUG in the published image (frd-followups A-10); 536 of 555 objects reference the assertion handler: 2026-09-14-image-build.md 4
so defects become observable where none could fire before. In pilot
deployments the loop reproduced a live open CIRCT issue from its first seed and
withheld it as a duplicate, % pilot 1: 3 of 3 probes fired, dedup known_open_issue #8508, 0 filings: 2026-09-16-pilot.md 0, 4, 5
at a total inference cost of about ten US dollars across all model calls. % 0.4867 + 0.4906 + 7.1640 + 0.8143 + 0.6416 = 9.60, plus one unmeasured attempt bounded 0.47-0.53: synthesis 9.3/10.4, pilot.md 0 and P2.2, pilot-3.md
\end{abstract}

\section{Introduction}
CIRCT is an open-source compiler for hardware. A designer writes how a circuit
should behave, in FIRRTL (the form the Chisel hardware language produces) or in
SystemVerilog, and CIRCT lowers it to Verilog, which synthesis and layout tools
turn into a chip. It is built on MLIR, the LLVM project's compiler
framework, and inherits LLVM's way of testing: a regression test carries the
command to run and the output to expect, run by a tool called \texttt{lit}. A bug that crashes
CIRCT is an inconvenience, seen and worked around; one that makes it emit wrong
Verilog is not: the output is well formed, passes the tools below it, and can
reach fabrication unnoticed.

CHIA \cite{chia} is the agent framework this hackathon is built on. Its CIRCT
issue solver chains six phases, from assessing an issue to reproducing, fixing,
verifying against the whole test suite, repairing regressions and writing the
pull request; on 16 CIRCT issues it fixed five, three of them merged.

Its supply is the constraint. Over the past year CIRCT received 82 bug-labelled
issues and closed 65; what does not drain is the backlog of 101 open ones, at a
median age of 911 days. % 82 bug-labelled issues, 65 closed, 101 open, median age 911 d: analysis/measurements/2026-09-13-frd-followups.md M1
The scarce resource is maintainer attention, and an agent that empties the queue
faster creates none. What would help is a bug that arrives already minimised,
already checked against what is known, already carrying a candidate fix, from a
source that files nothing else. Past fixes are the unspent information: a commit
that corrects one wrong assumption inside a pass usually leaves the same
assumption at other sites, and CIRCT ships no fuzzing infrastructure to find
them.

This paper describes a loop that manufactures its own supply and then withholds
most of it.

\section{The Loop}\label{sec:loop}
Fig.~\ref{fig:loop} names the stages and marks the ones the agent runs; tools
decide everything else. One model serves every agent stage, Gemini 3.8 Flash
through CHIA's Vertex backend, % model and backend, express mode: design/ADR/ADR-D-03-model-backend.md, superseding decision 2026-09-14
and no stage can build a client for it unless one environment variable
is set for that run, so a test or a dry run cannot reach the model. % live-call interlock BUGLOOP_ALLOW_LIVE_MODEL: ADR-D-03 rule (1); design/03-LLD.md 3.5.1

\textbf{Read the seed (1).} A seed is one of 187 CIRCT commits from the last two
years that look like bug fixes, with its diff and the test its author added or
changed. The agent reads both, states in one sentence the root-cause class
the fix corrected, and names other sites where the same assumption still
stands. % the SeedRecord carries that diff and those tests, so the worker needs no clone: design/00-README.md, seam rule

\textbf{Write probing inputs (2).} The seed's own test decides the language,
because its command line names the tool through which the bug was reachable:
\texttt{circt-opt}, \texttt{firtool} or the SystemVerilog front end. About 127 of the 187 seeds sit in code no FIRRTL input can reach, so
a FIRRTL-only generator would miss most of the corpus. The agent reads the
compiler's source and writes each candidate through tools of its own, and runs
no command.

\textbf{Build (3).} CIRCT compiles against one pinned commit of LLVM and MLIR,
and Section~\ref{sec:pre} explains how the loop avoids building those from
source. The build compiles in CIRCT's assertions, the internal checks its own
authors wrote, which stop the compiler the moment an assumption breaks.

\textbf{Judge (4).} An oracle is the rule that decides whether an input found a
bug. The primary one admits no argument: the compiler crashed, or an assertion
fired. A second runs the same design through CIRCT's simulator and
through Verilator, and treats disagreement as suspicious; it reports
only, because the two disagree routinely over uninitialised and reset signals.

\textbf{Reduce (5).} A crashing input is usually large and mostly irrelevant to
the crash. \texttt{circt-reduce}, which CIRCT ships, deletes parts of it and
keeps each deletion while the failure survives; a textual reducer takes over
where that tool dies.

\textbf{Triage and report (6).} Many failures are one failure, and deciding
which are the same is mechanical: a fingerprint is the assertion text with its
source location, or, for a crash, the symbolised frames left once the crash
handler's prologue is stripped. Survivors are matched against a local mirror
of CIRCT's open and closed issues and against commits made since the build
point. The agent writes the report, and no gate reads what it concluded. % gate reads no triage classification: design/03-LLD.md 3.9 (FR-13.4)

\textbf{Repair (7).} CHIA's phase chain runs unaltered but for one branch
selecting the backend the rest of the loop uses and an entry point taking a
local report in place of a GitHub issue. Repair is restricted to crashes and
assertion failures, where nobody has to argue about what the right answer was.

\textbf{The gates.} Between stages sit questions with two answers, the bars that
pinch the ribbon in Fig.~\ref{fig:loop}. A no ends the iteration and returns its
reason to the agent with the verdicts and reduced cases. The last is a gate of four questions, each
answered by a tool: does the failure reproduce in a fresh process on another
worker, is the case minimal, is the input valid, and is it new. % four mechanical gate questions: design/03-LLD.md 3.9 (FR-13.1)
The third is
three parse-and-verify commands, and a clean rejection makes the input the
loop's own fault rather than the compiler's. % gate question 3, the three commands: design/03-LLD.md 4.8 (FR-13.15)
Then the gate
is a person: a named author approves every filing at a command line, under a cap
on filings per day, and nothing is filed by default. % approval CLI, python -m circt_bug_loop.approve: design/03-LLD.md 16.2, 13.2 errata

\section{Measured Preconditions}\label{sec:pre}
The loop has to build CIRCT at arbitrary points of its history, and the compiler
has to be able to complain. Neither held when we started; Table~\ref{tab:meas}
is what we measured on the image the loop now runs.

\textbf{Building the past cheaply.} CIRCT records the exact LLVM commit it expects, its pin; a build against any other fails, and compiling that LLVM costs hours per seed. CIRCT also publishes an SDK of prebuilt LLVM and MLIR libraries carrying its own pin, and where the two pins match CIRCT rebuilds in minutes: 171 of the 187 seeds do.



The same mechanism fixes where the loop runs: not the newest commit of CIRCT's
main branch, whose pin has no published release today, but release-pinned main,
the newest commit whose pin has one, which for this image is 8 commits and 4.8
days behind the head. % lag measured at eade0de6 with SDK firtool-1.159.0: analysis/measurements/2026-09-14-image-build.md 1; ADR-D-10 first application
A long lag mechanically lowers the filing rate, because
more candidates come back already fixed.

\textbf{Letting the compiler complain.} Optimised builds delete assertions by defining the macro \texttt{NDEBUG}, and
CHIA's published CIRCT image is such a build: its binaries hold no reference to
the assertion handler, so a loop whose oracle is a failed assertion would find
nothing under it, whatever the agent wrote. One compiler
flag, \texttt{-UNDEBUG}, puts them back, and the image the loop runs is that
build at release-pinned main, with the flag in every compile command and the
handler back in all but 19 of its 555 compiler objects, which assert nothing. % 536 of 555 objects reference the handler: analysis/measurements/2026-09-14-image-build.md 4, FR-03.5

Whether the restored checks fire on CIRCT's own tests is what the oracle rests
on, so we built the image twice, differing in that flag alone, and ran CHIA's
whole test gate in both: the two runs pass the same 1,119 tests and fail none. % 1,119 of 1,127 considered, 0 failed, identical in both images: image-build.md 5 run 2 and W-04b 3
No test passes with assertions compiled out and fails with them compiled in, so
a probe that trips an assertion trips it because of what the probe does, and
Table~\ref{tab:meas} prices the flag.

One defect had to be repaired first: at CIRCT commits after mid-2026 a test
directory's configuration file raises while \texttt{lit} is discovering tests,
and CHIA's exclusion of that directory is applied after discovery, so the gate
discovered nothing. Pointing the build at the SDK as its MLIR source root, one
flag, restores discovery. % lit then discovers 1,390 tests with 0 parse errors: 2026-09-14-image-build.md 4 (FR-03.17) and 5
The binary still calls itself an optimised build,
so every report names the flag.

\textbf{Tested on real failures.} The oracle and its fingerprints were calibrated on real output: six past CIRCT
bugs, rebuilt at the commit before their fix and recorded with input, argument
vector and error output, in three classes across two SDK releases, 14\,s to
601\,s of build each. % six fixtures, three classes, two SDK tags, build costs: analysis/measurements/2026-09-14-crash-fixtures.md 1 and 2
Two defects in the fingerprinting rules appeared only
there: the name normaliser erased every frame in an anonymous namespace, which
is where CIRCT's passes live, and the scope test read an inlined frame instead
of the physical one, putting three of the four real bugs outside the repair
stage's reach. % the two frame defects: 2026-09-14-crash-fixtures.md 3.2 and 3.4; design/reviews/implementation-errata-log.md W-08 rows 1 and 2
Both are fixed.

\section{Controls}\label{sec:eval}
The experiment the loop embodies asks whether reading a past fix makes an agent
better at finding new bugs than mutating the same tests at random. Two arms
share the harness, oracles, reducer and gate, and only the generator differs:
the seeded arm is stages 1 and 2, and the mutation arm rewrites the same seed
tests syntactically without seeing the diff or the root-cause class, following
Mut4All's design for mutators synthesised by a language model \cite{mut4all}.
Both arms spend the same budget, a fixed window of wall-clock seconds, one after
the other on the same cluster at the same concurrency, and the artefact renders
one headline: distinct bugs a CIRCT maintainer confirmed by labelling,
commenting on or fixing them. Our oracle agreeing with itself produces a
candidate, not a bug.

\textbf{Pre-registration.} Every threshold lives in one budget file, and a run
is registered by an annotated git tag on the commit that lands that file; the
loop refuses a file no tag names and a mutator set committed after the tag, so
no threshold can be chosen after the fact. % registration/<run> tag, load_budget checks, mutator set must be an ancestor: circt_bug_loop/budget.py; docs/HANDOFF.md W-12b
Safety caps bound damage rather than effort: 2,000 generated inputs per arm per
day, 3 filings per day and 10 per run, 60 seconds and 4\,GiB per probe, and a
hard cap on model spending that stops both arms. % the caps: circt_bug_loop/budget.yaml
A run with a positive filing cap does not start until a human has posted the
method to the project's forum, and issues marked as good first issues are
refused. % pre-flight check 11 (FR-20.1), FR-20.2: circt_bug_loop/bug_loop.py check_11_forum_post

\textbf{Deduplication.} Two candidates are one bug when a single primary
fingerprint is equal. On a hand-labelled set of 22 candidate pairs the rule
collides on 1 of the 11 distinct pairs and falsely merges 1 of the 11 duplicate
pairs; % 22 labelled pairs, collision 1/11, false merge 1/11: design/reviews/implementation-errata-log.md W-10 row 20
both rates are printed beside the headline, since a collision inflates
that count and a false merge deflates it.

\textbf{Known issues.} A mirror of the tracker answers whether a candidate is
already reported. GitHub stops paginating an issue listing at its hundredth
page, which the loop met as an error and not as truncation, so the mirror walks
newest first, then oldest first, and unions the two: the whole tracker, 2,652
issues, 1,795 closed and 857 open, costs 198 requests and 200 seconds. % 422 at page 100: implementation-errata-log.md W-14 row 21; live mirror 2,652 issues (1,795 closed / 857 open), 198 pages, 200 s: docs/HANDOFF.md W-17 join

\textbf{Contamination.} CIRCT's history sits in the training data of any model
we can use, so the agent may reproduce a fix it memorised. Every candidate is
screened against fixes made after its seed, at the level of the symbols the
seed's fix touched: that screen flags 77\% of the corpus where the same screen
at file level flags 96\%. % symbol level 77.0%, file level 96.3%: analysis/measurements/2026-09-13-frd-followups.md M4
A real crash is a real crash, so the flag qualifies a candidate rather than
excluding it.

\section{Related Work}
SWE-bench \cite{swebench} scores agents on real GitHub issues and CHIA's issue
solver \cite{chia} applies the pattern to a hardware compiler; both draw from a
queue, and we fill one. Fuzzers fill queues without repairing or withholding:
CSmith \cite{csmith} for C, and for MLIR, MLIRod along operation dependencies
\cite{mlirod}, N\"uwa with a language model \cite{nuwa}, DESIL on silent
wrong-output bugs \cite{desil} and FLEX, 80 unknown bugs in 30 days \cite{flex}.
Our mutation arm follows Mut4All's synthesised mutators \cite{mut4all}. AFuzz
\cite{afuzz} is the origin of our method, an agent hypothesising where else a
reference bug's cause could live and testing each hypothesis, 40 bugs in V8 in
a month; we apply it behind a repair chain and a gate. Delta debugging
\cite{deltadebug} is stage 5's algorithm, and we contribute its placement.
Abstain-and-Validate \cite{abstain}, llvm-harness \cite{llvmharness} and
CodeRover-S \cite{coderovers} each make a repair agent more selective; our gate
sits downstream and discards by default.

\section{Artefact and Limitations}
We release the loop as CHIA nodes and tools, so swapping the generator for the
mutation arm is one node substituted. Its two halves meet at a frozen contract
of seven record types and one function call, version 2.2, tested separately
against recorded examples; % contract 2.2, tag contract-2.2: circt_bug_loop/contract/FROZEN.md
the suite is 634 tests, 594 of which need no cluster, network or model. % 2026-09-14 at HEAD d94fc42: 634 passed, 1 skipped with -m "not t2 and not t3"; -m t0 = 594
On CHIA's cluster layer the loop's five containers come up in 38 seconds and,
with a recorded generator, drive 16 probes through both arms in 7.4 seconds. % chia up 38.0 s: 2026-09-16-pilot.md 0; 16 probes in 7.4 s: docs/HANDOFF.md W-19b
Four things go upstream to CHIA: the Dockerfile for the assertions-on image, its
build workflow, three helpers for its CIRCT module, and the nineteen-line branch
that lets its repair chain select our backend. % upstream/: dockerfiles/ChiaCirctAssertDockerfile, .github/workflows/chia-circt-assert.yml, chia-chipyard-circt-additions.py, issue_task-vertex-branch.patch (19 insertions)
All of it, with the seed corpus and every input, verdict, reduced case,
transcript and gate decision, is at
\url{https://github.com/DevAbhinav-23/CHIA_Hackathon_2k26}.

The second oracle's harness generators emit, from one design, a CIRCT
simulation harness and a Verilator testbench printing identical 112-line
